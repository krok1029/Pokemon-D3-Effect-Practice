# CSV 重複主副屬性驗證

日期：2026-09-27。

## 問題與修正

自訂 CSV 若寫入 `Electric`／`electric`，兩者正規化後仍被建立為雙屬性，造成屬性平均樣本重複計算及防禦倍率重複相乘。

Mapper 現在於主副屬性正規化後、建立 Domain 物件前拒絕相同屬性。例如第二筆資料回報 `Row 2: column "Type 2" must differ from "Type 1"`。不靜默去重或猜測原本的副屬性；空白／none 副屬性與不同的合法雙屬性沿用既有行為。

## 驗證

```bash
yarn test:unit tests/infra/csv
```

- Mapper 新增同大小寫、不同大小寫及帶空白的 3 項重複屬性案例，皆驗證包含筆次與 `Type 2` 的完整錯誤訊息。
- 真實 CSV 整合案例以合法第一筆、重複屬性第二筆載入 Repository → UseCase，確認整批在輸出 DTO 前拒絕，報錯為第二筆。
- 原有 18 種屬性正規化案例改用循環錯開的副屬性；仍完整核對所有 18 種主、副屬性的正規化值，避免用不存在的同屬性組合當合法資料。
- 修改產品前，重複屬性的 4 項新案例均失敗；舊行為直接輸出 `Electric`／`Electric` DTO。
- 修正後 CSV 測試 5 檔、77 項通過，包含正式資料 1,032 筆／898 個編號／125 筆傳說及現有 fixture。原有合法雙屬性分組、平均值、篩選與相剋整合斷言亦通過。

與 BOM 修正共用本輪 CSV 驗證。正式 CSV 沒有重複主副屬性，本次沒有修改來源資料或 App／Core 算法。
