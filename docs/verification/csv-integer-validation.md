# CSV 整數欄位驗證

日期：2026-09-26。

## 問題與修正

`CsvPokemonMapper` 原先使用 `parseInt` 與 `Math.trunc`，會把 `35oops`、`35.9` 接受成 `35`，且接受超出 JavaScript 安全整數範圍的值。

編號與六項能力現在只接受完整十進位整數字串或安全整數數值；保留前後空白、前置零與正負號的解析，正值與能力範圍仍由既有 Domain 規則檢查。小數格式（含 `35.0`）、科學記號、十六進位、空值與超出安全範圍的整數均拒絕。錯誤訊息包含第幾筆資料（從 1 起算，不含標題列）與原始 CSV 欄位名稱。

此修正不改動 CSV、型態識別、傳說欄位或快取行為。

## 驗證

- 修正前執行 `yarn test:unit tests/infra/csv/CsvPokemonMapper.test.ts`：新增案例捕捉到 14 個失敗，其中包含原問題的數字前綴與小數截斷。
- 修正後 Mapper 與既有 Repository 測試共 28 項通過。
- 再加入正式 CSV 相容性驗證後，Mapper 27 項通過：逐筆比對 1,032 筆資料的編號與六項能力，確認 898 個不同圖鑑編號，沒有數值截斷或資料排除。

整體回歸結果另見 [平行修正驗收](parallel-fixes-2026-09-26.md)。
