# Roadmap 第一批驗收

日期：2026-09-19。範圍為當時未受阻擋的 #14、#15、#17、#18。使用者已授權確定需求後調整對應測試；以公開頁面及網址為主要驗收入口。

## 環境

- Node.js 20.19.0、全域 Yarn 4.18.0；專案指定 Yarn 4.9.4。
- Next.js 15.4.6；沿用已安裝依賴，未升級套件。
- 本機隔離工作副本使用預設 CSV，1032 筆型態樣本、898 個編號；排除傳說後 907 筆、806 個編號。
- 瀏覽器驗收服務使用 `http://127.0.0.1:3100`。設定 `PLAYWRIGHT_BASE_URL` 時只連到外部服務，不自動再啟動第二個服務；未指定時維持原本的自動啟動流程。

## 行為驗收

- #14：一般對幽靈 0×；火對水 0.5×、一般 1×、草 2×；噴火龍雙屬性選最佳攻擊；防禦岩石 4×、地面 0×、草 0.25×。頁面列表與雙環圖標籤一致，說明不含本系加成等戰鬥條件。無屬性時維持空相剋資料；此資料不符合 Domain 輸入限制，因此在 ViewModel 呈現邊界驗證。
- #15：三種噴火龍卡片及型態網址、六項能力、屬性、metadata、刷新、地區型態、舊網址與錯誤網址。真實 CSV 的頁面 metadata 入口另外驗證資料重排、身份碰撞及 Mega 先出現時的穩定預設型態。
- #17：首頁入口、390px 手機與桌面導覽、metadata、移除死連結、動態型態樣本與編號數、雙屬性分組說明、排除傳說後計數。另以 4 列／3 個編號的自訂 CSV 驗證沒有寫死正式資料數字。
- #18：組合篩選網址、控制項、刷新及分享、清除、上一頁／下一頁、連續輸入、無效參數、空結果、主副屬性及既有搜尋語意；詳細頁刷新後返回原條件與卡片位置，以及缺少／無效來源的回退。

各功能在修正前先取得對應失敗案例，再驗證修正後通過；新增的既有行為回歸案例不刻意破壞程式製造失敗。

## 可重現指令

正常開發環境可執行 `yarn typecheck`、`yarn lint`、`yarn test:unit`、`yarn build`、`yarn test:e2e`。此次隔離副本沿用原專案的已安裝依賴，直接執行對應套件入口。

外部服務驗收：

```bash
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3100 yarn test:e2e --workers=1
```

自訂資料必須先停止預設服務，再重新啟動（Repository 會快取 CSV）。本批也驗證了先以預設資料建置，再於正式服務啟動時改用自訂資料，無須重新建置：

```bash
POKEMON_DATA_PATH=tests/e2e/fixtures/navigation.csv yarn dev --hostname 127.0.0.1 --port 3100
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3100 POKEMON_E2E_DATASET=custom yarn test:e2e tests/e2e/navigation.spec.ts --project=chromium --workers=1
```

正式環境驗收時，先 `yarn build`，將上方啟動指令的 `yarn dev` 換成 `yarn start`，其餘參數及驗收案例相同。

## 檢查結果

| 檢查 | 結果 |
| --- | --- |
| TypeScript | 通過 |
| ESLint | 通過，0 錯誤、0 警告 |
| Vitest 完整測試 | 19 檔、46 個案例通過；後續修正另重跑 3 檔、10 個相關案例通過 |
| 初次完整三瀏覽器流程 | 123 個執行案例：122 通過、1 個 WebKit 搜尋案例失敗；原因及修正如下 |
| 修正後三瀏覽器搜尋流程 | 14 個案例 × 3 種瀏覽器，共 42 個執行案例通過 |
| 修正後三瀏覽器倍率流程 | 9 個執行案例通過 |
| Next.js 正式建置 | 通過；首頁、圖鑑、詳細頁及圖表均使用請求時資料 |
| 最終正式版本、預設 CSV、Chromium | 42 個案例通過 |
| 最終正式版本、自訂 CSV、Chromium | 7 個案例通過，使用與預設資料相同的正式建置 |

首次完整瀏覽器驗收發現 WebKit 可在 React 完成初始化前輸入，導致關鍵字未進入網址便遺失。延遲載入互動程式的頁面案例可穩定重現；現在使用尚未就緒時停用的篩選控制，修正後原失敗流程連續 5 次通過，沒有放寬斷言或增加重試掩蓋問題。

正式環境驗收另發現首頁與圖鑑會沿用建置時預先產生的 CSV 資料，與動態圖表不同。先用自訂資料取得 2 個失敗／1 個通過的案例，再設定首頁與圖鑑動態呈現；自訂資料的全部 7 個案例隨後通過。

並行開發期間曾遇到 `.next` 產物衝突，且驗收工具出現自動啟動另一個服務的記錄；清除產物、重啟單一服務後重新驗收。外部 `PLAYWRIGHT_BASE_URL` 現在不會觸發自動啟動，正式建置亦使用獨立副本，避免干擾正在測試的服務。

## 剩餘限制

- #16：型態圖片仍沿用編號索引，Mega 圖片可能不一致，四位數檔名仍待修正。
- #19：完整圖鑑仍一次建立與渲染符合條件的卡片，列表仍有不必要的詳細相剋組裝；尚未提供分段瀏覽。
- #20：散佈圖框選結果尚未連到型態詳細頁。
- `formId` 由名稱產生；只保證資料重排穩定，來源名稱改名時需另設轉址策略。舊編號網址以最短名稱、再英文名稱順序選定預設型態，並非任意資料來源的基本型態分類器。
