# #23 散佈圖縮放與平移裁切

日期：2026-09-26。

## 修正行為

散佈圖每個實例建立唯一的 SVG `clipPath`，範圍等於實際繪圖區，只套用在資料點圖層。座標軸、標題及框選圖層維持完整；點的標題與詳細頁資料保持原有行為。縮放與平移仍更新點座標，超出範圍的繪圖像素由瀏覽器裁切。能力軸與資料範圍更新時重建相同範圍的裁切，SVG 縮放時共同套用 viewBox。

## 頁面與畫面回歸

`tests/e2e/chart-clipping.spec.ts` 使用實際放大／縮小按鈕、滑鼠框選與中鍵平移：

- 預設物攻／HP、排除傳說，連續放大六次。
- 切換特攻／速度、變更傳說條件及視窗寬度後重做驗收。
- 放大、中鍵平移及縮小三種畫面，各保存散佈圖截圖；另外取得同畫面暫時隱藏資料點的截圖，逐像素確認繪圖區外沒有資料點改變畫面、繪圖區內仍有資料點。兩像素邊界容差僅處理 CSS／截圖座標四捨五入。
- 框選仍能產生結果，中鍵平移清空舊選取，重新框選後提供型態詳細頁連結；保留點的 title。

## 本機靜態驗證

元件及新增 E2E 檔案的 ESLint、Prettier 檢查通過；全專案 `tsc --noEmit --incremental false` 通過。既有 `chart-detail-links.spec.ts` 仍負責各 Charizard 型態、鍵盤開啟、刷新與分享網址的完整回歸。完整整合與遠端 CI 結果記錄於 [#25](https://github.com/krok1029/Pokemon-D3-Effect-Practice/issues/25)。

隔離正式建置驗證：預設軸案例在 Chromium／Firefox／WebKit **3／3 通過**；切換能力、傳說條件與較窄視窗後的案例 **3／3 通過**。第二組先修正 checkbox 的非同步等待，再重跑；兩組均涵蓋放大、平移、縮小的畫面像素及框選行為。

另以尚未包含裁切修正的隔離正式建置作為反向驗證：Chromium 桌面案例在連按六次放大後，如預期偵測到繪圖區外 **7,165 個受資料點影響的像素**而失敗。這確認像素斷言能抓到原始溢出問題，並非只檢查 `clipPath` 屬性存在。
